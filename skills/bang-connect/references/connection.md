# 连接、权限与恢复

## 授权边界

BANG 使用网站服务器发起、按浏览器账户隔离的官方 Agentic Wallet 配对会话。授权凭证保存在平台的该账户隔离空间，供网页请求钱包签名；它不是用户 AI 内的本地钱包会话。平台不要求用户提供私钥。用户应在官方 App 确认所授权的会话，并自行选择额度和期限。

网页连接钱包、Developer Mode、Agent ID 资格与 ERC20 approve 是四件事：

| 状态 | 如何获得 | 有效范围 |
| --- | --- | --- |
| 网页配对 | 币安 App 批准页面的官方配对请求 | 当前浏览器账户 |
| Developer Mode | 用户在官方钱包设置额度与期限 | 钱包允许的外部合约调用；仍受其风控限制 |
| Agent ID 买入资格 | 目标发射台实时合约检查 | 具体代币、市场阶段与钱包地址 |
| ERC20 allowance | 用户确认对明确 spender 的授权交易 | 对应代币与合约，默认仅本次数量 |

## 网页状态机

未连接 → 等待 App 配对 → 已连接 → 开启限额快捷交易 → 选择已支持的代币 → 用户点击买入/卖出 → 后台报价/链上模拟/官方钱包预览 → 按已授权范围提交 → 待 App 确认或已广播 → 回执确认。

快捷授权包含每笔和每日买入 BNB 上限、滑点、期限，以及必要的包装和精确授权。买入完整预算在准备开始时计入 UTC 当日限额，失败或退款不自动释放额度；这使超时与重试不会扩大可支出范围。卖出按用户每次输入数量，不能超过当前余额。用户新授权明确接受官方非拦截风险提示，这些报告仍逐笔保留；官方拦截不能绕过。未知广播结果只能恢复原订单。关闭网页可能暂停后续步骤，重新进入可继续同一订单。

“已连接”不等于全部代币可买。进入交易前，网页必须复核当前钱包、chain 56、权限到期、额度、Agent ID、当前持仓、发射台和市场阶段。内盘与毕业后的 DEX 不能互换路由。平台尚未接入的来源只展示数据。

钱包不支持直接网页钱包插件接入时，不能把 MetaMask 连接假装成 Binance Agentic Wallet 的配对。采用平台实际支持的官方配对机制。

## 常见恢复

- 配对过期：取消旧配对，再在同一浏览器请求新配对。
- 已在 AI 登录但网站未连接：在网站单独配对；不导出 AI 凭证。
- 换浏览器、无痕窗口或清除 Cookie：可能是新的平台账户；重新配对自己的钱包。
- Developer Mode 关闭、到期或限额不足：由用户在官方 App 调整，然后在网页刷新。
- Agent ID 不符：不能用平台 ID 替代；按官方领取流程处理，重新校验目标协议。
- 钱包返回额外确认：到币安 App 处理同一订单，保持网页原订单，不重复购买。
- 超时/未知提交：通过原订单和链上哈希恢复。没有确认失败前不自动重发。
- 断开：网页立即使旧预览失效；如官方 signout 未确认成功，提示用户去 App 检查。交易历史仍可用于核验已广播交易。

## 公开辅助接口

`GET /api/integration` 返回版本、固定网络、授权模式、页面路径和已接入能力；没有钱包凭证。`scripts/connect.mjs` 只访问这个接口，不携带 Cookie、不签名、不请求任意合约。

网页的 `/api/live/*` 是受浏览器账户 Cookie 与同源写请求约束的私有业务接口，不是给其他网站或 AI 复制凭证调用的开放签名 API。不要指导用户复制 Cookie、session token 或 requestId。

RWA 买入额度按固定目录报价合约的 30 分钟均价折算，并预留 10% 估值余量，签名前再次检查；官方钱包的每日额度另外独立执行。旧快捷授权不自动扩大到 RWA，用户需在额度页重新确认。
